# QuietZone 技能包

本目录存放从本项目协作过程里沉淀下来的可迁移技能。每个技能是一个独立目录，内含 `SKILL.md`
（给智能体读的工作流）和可选的 `scripts/`（可直接运行的脚本）。技能只写"怎么用、用到什么程度算完成、
什么情况下不适用"，不绑定本项目的题目、板卡或文件树——换一个 FPGA 题目仍然可用。

| 技能 | 解决的问题 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| `competition-rules-intake` | 把赛事指南、模板和提交限制转成可执行的要求清单 | 官方 PDF/DOCX、提交页截图 | 要求-证据映射表、阻断项 |
| `evidence-driven-engineering-report` | 用源码、报告、日志和实测材料写技术报告 | 工程文件、综合实现报告、测试记录 | 带验证状态的技术报告 |
| `submission-package-audit` | 提交前审计目录结构、命名、复现步骤和材料完整性 | 提交包目录 | 审计结论、缺件清单 |
| `vivado-gui-evidence-capture` | 在 Vivado/Vitis 真实界面中采集仿真、综合、实现证据截图 | 工程、目标状态、输出目录 | 可复核的界面截图与元数据清单 |
| `pynq-overlay-bringup` | 在 PYNQ 上加载校验 Overlay，把 XSA/HWH 变成可执行的寄存器访问与冒烟测试 | XSA/bit + 寄存器契约 | 调用骨架、冒烟脚本 |
| `pynq-dma-golden-verify` | DMA 搬运与缓存一致性封装，黄金比对加吞吐与资源报告 | DMA IP + 黄金参考 | 比对结果、吞吐表、报告行 |

## competition-rules-intake

- **适用场景**：拿到一份（或几张截图形式的）赛事/评审规则，需要在动手写代码前先明确"要交什么、
  每条要求用什么证据满足"。也适用于内部评审标准和交付检查。
- **使用方法**：① 把规则逐条抄成条目，不改写、不合并；② 每条标注"必须/加分/参考"；
  ③ 给每条指定唯一证据位置（文件名/章节号）；④ 找不到证据的条目单列为阻断项；
  ⑤ 交付前回来逐条打勾，不允许"看起来写了"。
- **已验证效果**：本包用它将四张规则截图拆成工程包 5 项、设计报告 7 项、技能包 4 类，
  每项都能指到 `report/`、`build/screenshots/`、`sim/logs/` 下的具体文件；
  也正是这一步发现了"优化前后对比表"缺失，补写为报告 §3.6。
- **失效条件**：规则本身含糊（例如只说"性能优良"没给指标）时，先向主办方确认，
  不要用自造指标填空；规则版本更新后必须重跑，旧清单不算数。
- **来源（失败观察）**：早期按经验组织交付包，结果漏掉"优化前后对比表"和"复现步骤"，
  评审模板逐条对照才发现——从此把"先拆规则再动手"固化成第一步。

## evidence-driven-engineering-report

- **适用场景**：写技术报告、答辩材料、验收文档，且评审会追问"这个数字哪来的"。
- **使用方法**：① 每个结论先找到原始输出（`.rpt` / 日志 / 样本 JSONL / 截图）；
  ② 在正文里写"数字 + 出处"；③ 给结论打状态：已验证 / 部分验证 / 未验证 / 未实现；
  ④ 换版本后重跑证据，不允许把旧报告的数字搬到新报告。
- **已验证效果**：报告摘要曾引用早期 PL-only 版本的 9,148 LUT / 18,692 FF，
  与随包位流的 4,187 / 4,614 不符；按本流程逐项回溯 `impl_1` 报告后全部改正，
  并在报告中把功耗明确标为 Vivado 估算值而非实测。
- **失效条件**：没有原始输出时不要"补一个合理数字"，只能写"未验证"；
  只有截图没有可复现命令时，证据等级按"部分验证"处理。
- **来源（失败观察）**：一次交付前核对发现报告与位流不是同一版本，数字全对但互相矛盾——
  这比数字错更难发现，因此把"数字必须能追到同一份报告"写成硬规则。

## submission-package-audit

- **适用场景**：打包提交前，或把工作目录整理成交付目录时。
- **使用方法**：① 对照官方目录结构逐层核对，多一层少一层都算问题；
  ② 检查命名：小写英文、数字、下划线/连字符，无中文、无空格；
  ③ 检查可复现：脚本里不得有本机绝对路径，构建/仿真命令能直接跑；
  ④ 检查证据链：报告引用的每张图、每个数字都能在包内找到；
  ⑤ 输出"缺件清单 + 阻断项"。
- **已验证效果**：本包审计出三类问题并修掉——`src/bd` 里留着已废弃的 `audio_core` 建库脚本、
  上板脚本硬编码 `C:\Users\...` 与本机 ELF 路径、报告目录为空；
  修正后 8 个顶层条目齐全，`sim/run_sim.ps1` 与 `build/build.ps1` 在干净目录可直接运行。
- **失效条件**：包内文件本身不完整（例如位流没生成）时，审计只能报缺件，不能替代构建；
  对二进制产物只做存在性与大小检查，不做内容正确性判断。
- **来源（失败观察）**：第一次整理时把工作目录原样复制，中文文件名、临时截图、
  指向旧工程绝对路径的脚本一起进了包，被"换台机器能否复现"一问就露馅。

## vivado-gui-evidence-capture

- **适用场景**：需要在报告/答辩里证明"工具真的跑过"，例如仿真波形与控制台 PASS、
  实现后时序资源仪表板、模块级综合视图。
- **使用方法**：① 先固定"这张图证明什么"，再决定界面；② 用 Tcl 把 Vivado 带到目标状态
  （`open_project` / `launch_simulation` / `open_run impl_1`）；③ 等渲染完成再截；
  ④ 截图进程必须声明 DPI 感知，否则 150% 缩放下会得到降采样图；
  ⑤ 每张图记录界面状态、进入命令、能证明的结论（见 `build/screenshots/capture_manifest.md`）。
- **已验证效果**：本包 4 张图全部来自 Vivado 2026.1 真实窗口（2560×1600 原生），
  波形图对应的仿真在 1,964,610 ns 打印 `>>> PASS <<<`，仪表板同一屏可见 WNS +1.135 ns
  与 4187 / 4614 / 34 / 7 的层次资源；每条都能用清单里的 Tcl 命令重进该界面。
- **失效条件**：无桌面会话且未配置虚拟显示时不适用；只需要数值结论时直接用 `.rpt`，
  截图只会增加体积；界面语言/版本差异导致菜单名不同，应改用 Tcl 而非点菜单。
- **来源（失败观察）**：早期用重绘图充当仿真截图，评审无法确认真跑过；
  改用真实窗口后又遇到两个坑——`SendKeys` 经输入法把空格变成中文、未声明 DPI 感知导致截图被降采样，
  两条都写进了技能的"失败条件"。

## pynq-overlay-bringup

- **适用场景**：板卡已装 PYNQ 镜像（2.7/3.x），手上只有 Vivado 的 bit/XSA 和一张寄存器表，需要不写裸机 C 就把 PL 加速器跑起来，并证明"真的能读写"。
- **使用方法**：① 位流与 `.hwh`/`.xsa` 同名同目录；② 加载后先用 `is_loaded()` 与 `ip_dict` 自检，不写死 IP 名；③ 按契约用 `MMIO` 或 `register_map` 访问，每个 rw 寄存器写后回读；④ 由契约 CSV 生成访问类与 pytest 骨架；⑤ 冒烟脚本四步走（读版本 → 写读 → 最小事务 → PASS），退出码 0 才算完成。
- **已验证效果**：本工程 `0x4000_0000` 寄存器堆与 `0x4002_0000` 帧存的地址表与 BD 分配逐项一致，`src/host/hw_ifc.py --mock --selftest` 在本机全项通过；未在 PYNQ 镜像上实机加载，标为"部分验证"。
- **失效条件**：只有 `.bit` 没有 `.hwh`/`.xsa`（无法反推 IP 名与地址）；需要微秒级确定性时延（用户态调度做不到）；板卡只跑裸机 ELF 时应改用 Vitis + JTAG 流程。
- **来源（失败观察）**：本工程用 `/dev/mem` 访问时真实遇到"读未映射地址 → AXI SLVERR → SIGBUS 直接打死进程"，Python 的 `try/except` 抓不住，从此把"存在性探测放子进程"写成硬规则；另一次换板卡后脚本全挂，原因是写死了带层次前缀的 IP 名。

## pynq-dma-golden-verify

- **适用场景**：PL 侧有 AXI DMA / AXI-Stream 通路，需要回答"数据对不对、带宽多少、和参考差多少"，并把结果自动写进报告。
- **使用方法**：① 缓冲一律 `allocate()`；② 先 arm 接收再发发送，`wait()` 带超时；③ 发送前 `flush()`、接收后 `invalidate()`；④ 黄金比对用整数全等或相对误差，比较前统一 dtype 与端序；⑤ 每次测量记录字节数、耗时中位数、吞吐，并把 `.rpt` 的资源时序并排写进同一张表。
- **已验证效果**：本工程帧存通路（28800 字 RGB565）用 `hw_ifc.py --fb-pattern/--fb-check` 做过写读一致性核对；`data/golden/frame_window_256x8.coe` 与 `gen_frame_window.py` 的汉宁窗公式逐点一致（256 点、峰值在第 125 点）。DMA 实机搬运未在 PYNQ 镜像上跑过，标为"部分验证"。
- **失效条件**：数据量只有几十字节（MMIO 更快）；DMA 未分配地址（先做 Overlay 冒烟）；需要确定性时延。
- **来源（失败观察）**：早期把 `np.zeros()` 的缓冲交给 DMA，数据偶发错位，最后定位到页不连续；另一次传输后没 `invalidate`，回读永远是上一包——两个现象现在直接进故障表。

## 通用约定

- 截图、日志、报告必须能追溯到具体命令与时间，禁止用示意图冒充实测结果。
- 目录与文件名使用小写英文、数字、下划线和连字符。
- 结论分为"已验证 / 部分验证 / 未验证 / 未实现"四档，不得混写。

## 整个技能包的失效条件

- 目标环境缺少对应工具链（如没有 Vivado），且无法用等价工具复现时，技能不适用。
- 需要的数据本身不存在（例如从未上板），任何技能都不能替代真实测量。
